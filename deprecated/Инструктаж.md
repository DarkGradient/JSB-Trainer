# РУКОВОДСТВО ПО АРХИТЕКТУРЕ ТРЕНЕРА (JSaB Trainer)

## 1. Философия системы: Полная отвязка (Pure Decoupling)

Главная проблема большинства модов — **жесткая связь (Tight Coupling)**. Если класс отображения (`HUDManager.cs`) напрямую опрашивает свойства модулей или содержит хардкод их имен и настроек, то при удалении любого файла (например, `Noclip.cs` или `OneHit.cs`) весь проект перестает компилироваться.

Наша архитектура решает эту проблему за счет концепций **реактивного реестра, текстовых ID и чистого отображения (Pure View)**:
* **Классы геймплея** (например, `Noclip.cs`, `OneHit.cs`) занимаются **только геймплеем**. Они полностью автономны.
* **Слой отображения** (`HUDManager.cs`) является **чистым холстом**. Он вообще ничего не знает о существовании конкретных читов, их состояниях или названиях.
* **Связующий механизм**: Модули при инициализации сами «регистрируют» свои графические элементы и плашки в `HUDManager`, передавая ему нужные цвета, размеры шрифта, позиции и функции-делегаты для чтения текста и активности. 
* Если вы удалите любой файл чита, **проект скомпилируется без единой ошибки**. Чит просто не успеет зарегистрировать свои кнопки в меню и плашки на экране, и они бесшовно исчезнут из игры.

## 2. Мозг системы: `ModuleRegistry.cs`

Этот класс отвечает за автоматический поиск ваших скриптов в проекте и хранение их настроек для меню `UI.cs`.

### А. Автоматический поиск (Рефлексия)
При запуске игры `Main.cs` вызывает один единственный метод: `ModuleRegistry.InitializeAll(harmony)`. 
Реестр сканирует все файлы вашего проекта и автоматически подключает их по следующим правилам:
1. **`Initialize`**: Если в вашем классе есть статический метод `Initialize(HarmonyLib.Harmony)` или `Initialize()`, реестр его запустит. Там обычно регистрируются патчи Harmony, кнопки в меню и плашки на экране.
2. **`Update`**: Если в классе есть статический метод `Update()`, реестр запишет его в свой цикл обновлений и будет вызывать **каждый кадр** (из `Main.OnUpdate()`).
3. **`OnGUI`**: Если в классе есть статический метод `OnGUI()`, реестр будет вызывать его **каждую отрисовку кадра** (из `Main.OnGUI()`).

### Б. Регистрация настроек меню
Чтобы добавить чекбокс или слайдер в меню `UI.cs`, модуль должен зарегистрировать его во время своей инициализации:

```csharp
// Чекбокс (галочка в меню)
ModuleRegistry.CreateHUD(
    category: "Gamemodes",          // Категория: "Gamemodes" или "Optional Stuff"
    name: "One-Hit Mode",           // Текст в меню настроек
    getter: () => Enabled,          // Функция чтения значения
    setter: (val) => Enabled = val, // Функция записи значения
    isLocked: () => false,          // Callback блокировки (или null, если всегда доступно)
    order: 10                       // Сортировка сверху вниз (меньше = выше)
);

// Слайдер (ползунок в меню)
ModuleRegistry.RegisterSlider(
    category: "Optional Stuff",
    name: "My Slider",
    defaultValue: 0.5f,             // Дефолтное положение (от 0.0f до 1.0f)
    onChanged: (val) => { ... },     // Callback изменения значения
    order: 70
);
```

## 3. Слой отображения: `HUDManager.cs`

Этот файл отвечает за всё, что рисуется на экране поверх игры, кроме самого меню настроек. Он не содержит никаких прямых упоминаний ваших чит-модулей.

### А. Сетка позиционирования на 9 зон (`HUDPosition`)
В системе реализована полноценная разметка экрана на 9 позиций (3х3):
```csharp
public enum HUDPosition
{
    TopLeft,      TopCenter,      TopRight,
    MiddleLeft,   Center,         MiddleRight,
    BottomLeft,   BottomCenter,   BottomRight
}
```
Вы можете разместить любую плашку или всплывающее уведомление (Toast) в любую из этих зон. Текст автоматически выровняется по левому краю, по центру или по правому краю в зависимости от выбранной стороны экрана.

### Б. Честный математический авто-размер (`CalcSize`)
Все плашки и всплывающие баннеры используют встроенную функцию Unity — `GUIStyle.CalcSize` [4]. Менеджер на лету рассчитывает точный размер текста в пикселях с учетом индивидуально заданного размера шрифта, добавляет аккуратные внутренние отступы и **самостоятельно масштабирует подложку коробки под любые габариты текста** (даже если в нем много строк) [4].

### В. Динамическое накопление стека по зонам
Каждая из 9 позиций экрана имеет свою собственную независимую очередь стека. Если вы включите несколько плашек в одной зоне, они выстроятся в красивую цепочку:
* **Вверху (Top...)**: плашки аккуратно выстраиваются друг под другом **вниз** (+).
* **Внизу (Bottom...)**: плашки красиво выстраиваются друг над другом **вверх** (-) (чтобы не улетать под экран).
* **Посередине (Middle... / Center)**: вся пачка плашек автоматически **центрируется по вертикали** относительно середины экрана.

Если одна из промежуточных плашек выключается, все плашки под ней плавно и бесшовно сдвигаются на освободившееся место.

### Г. Всплывающие уведомления (Toast)
Метод `HUDManager.CreateToast` плавно выдвигает темную плашку с текстом, удерживает её и плавно скрывает с эффектом скольжения (slide offset). Каждое уведомление плавно угасает независимо и имеет свою индивидуальную позицию на экране.

## 4. Пошаговое руководство: Как создать новый модуль

Давайте создадим абсолютно новый чит «Режим призрака» (`GhostMode.cs`), задействовав все элементы нашей отвязанной архитектуры.

### Шаг 1. Создаем файл `GhostMode.cs`
Создайте пустой файл в папке проекта. Пропишите namespace `jsb_new` и добавьте директивы отключения предупреждений компилятора:

```csharp
#pragma warning disable CS8618 // Поля, не допускающие значения NULL
#pragma warning disable CS8600 // Преобразование null

using HarmonyLib;
using Il2Cpp;
using UnityEngine;

namespace jsb_new
{
    public static class GhostMode
    {
        private static bool _enabled = false;

        // 1. Свойство состояния чита, завязанное на реактивный реестр
        public static bool Enabled
        {
            get => ModuleRegistry.IsActive("GhostMode");
            set
            {
                if (_enabled != value)
                {
                    _enabled = value;
                    ModuleRegistry.SetActive("GhostMode", value);
                    
                    // === ОТПРАВЛЯЕМ TOAST-УВЕДОМЛЕНИЕ ПРЯМО ОТСЮДА ===
                    if (value)
                        HUDManager.CreateToast("GHOST MODE ON", Color.cyan, duration: 2.0f, position: HUDPosition.BottomCenter);
                    else
                        HUDManager.CreateToast("GHOST MODE OFF", Color.white, duration: 2.0f, position: HUDPosition.BottomCenter);
                }
            }
        }

        // 2. Метод инициализации (реестр найдет его сам на старте)
        public static void Initialize(HarmonyLib.Harmony harmony)
        {
            // Регистрируем галочку в меню UI (появится в категории Optional Stuff)
            ModuleRegistry.CreateHUD(
                category: "Optional Stuff",
                name: "Ghost Mode",
                getter: () => Enabled,
                setter: (newValue) => { Enabled = newValue; },
                isLocked: null,
                order: 25 // Встанет в меню между Noclip (20) и Hitboxes (30)
            );

            // РЕГИСТРИРУЕМ ПЛАШКУ В HUD-МЕНЕДЖЕРЕ!
            // Она будет плавно мигать из белого цвета в циан, иметь размер шрифта 18
            // и отображаться в позиции TopRight (правый верхний угол)
            HUDManager.RegisterRightPlate(
                key: "GhostMode",
                textGetter: () => "GHOST ACTIVE",
                baseColor: Color.white,
                pulseColor: Color.cyan,
                activeGetter: () => Enabled,
                height: 35f, 
                order: 25,
                fontSize: 18,
                position: HUDPosition.TopRight
            );

            // Регистрируем наши Harmony-патчи (если они нужны для работы чита)
            // HarmonyLib.Harmony.CreateAndPatchAll(typeof(Patch_GhostCollision));
        }

        // 3. Метод Update (реестр найдет его сам и будет вызывать каждый кадр)
        public static void Update()
        {
            // Хоткей: переключаем по нажатию на клавишу L
            if (Input.GetKeyDown(KeyCode.L))
            {
                Enabled = !Enabled;
            }

            if (!Enabled) return;

            // Любая ваша логика, выполняемая каждый кадр при включенном чите
        }
    }
}
```

Всего один файл! Нам не пришлось писать ни строчки GUI-кода, не пришлось лезть в настройки HUD и вручную расставлять плашки. Чит готов к работе и полностью интегрирован во все системы.

## 5. Справочник API (Шпаргалка разработчика)

### Категории для UI Меню настроек
В методе `ModuleRegistry.CreateHUD` используйте строго эти строки в аргументе `category`, чтобы меню группировалось правильно:
* `"Gamemodes"` — верхняя часть меню (для основных игровых режимов).
* `"Optional Stuff"` — нижняя часть меню (вспомогательные тумблеры и настройки).

### Сортировка кнопок в UI (`order`)
Используйте эти цифры, чтобы сохранять идеальный порядок кнопок в меню:
* **Категория "Gamemodes":**
  * `10` — One-Hit Mode
  * `11` — True One-Hit (Beta)
  * `20` — Purple SOUL Mode
  * `30` — Orange SOUL Mode
  * `40` — Mouse Control
* **Категория "Optional Stuff":**
  * `10` — Enable Audio Visualizer
  * `15` — Show Level Info HUD (левая плашка)
  * `20` — Noclip
  * `30` — Hitboxes
  * `40` — Always black BG
  * `50` — Hide Timeline
  * `60` — FPS Unlock
  * `70` — Dash Cooldown (слайдер)

### Сортировка плашек в HUD (`order`)
Используйте эти цифры при вызове `HUDManager.RegisterRightPlate`, чтобы плашки в правом верхнем углу выстраивались в красивом приоритете сверху вниз:
* `10` — One-Hit Status (крупный блок на 2 строчки)
* `20` — Noclip Status (одна строчка)
* Любые ваши новые плашки создавайте с шагом приоритета (например, `15`, `25`, `30`), чтобы они гармонично вставали между ними.

### Вызов всплывающих оповещений (Toasts)
Вы можете отправлять баннеры на любую из 9 позиций экрана:
```csharp
// По умолчанию (снизу по центру)
HUDManager.CreateToast("PREFERENCES SAVED", Color.green);

// По центру вверху экрана
HUDManager.CreateToast("READY TO PLAY", Color.cyan, duration: 2.0f, HUDPosition.TopCenter);

// В левом нижнем углу
HUDManager.CreateToast("DISCONNECTED", Color.red, duration: 3.5f, HUDPosition.BottomLeft);
```
